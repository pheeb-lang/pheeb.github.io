# 文件知識庫與 RAG 問答互動展示

此目錄即完整可複製的靜態成品，入口為 `index.html`，無需 build、安裝套件、登入、API 或原專案。資料及 AI 回覆皆為模擬；不提供正式知識檢索。

## 展示範圍

保留深色側欄、藍色主色、白色卡片、16px 基準與響應式佈局。文件統計、資料夾篩選、標題／資料夾搜尋、狀態及格式篩選、列表／卡片與每頁 10 筆分頁皆可操作。初始 22 份可見文件分為 3 頁，另有 1 份已刪除文件驗證排除規則；提供 4 個資料夾、8 個標籤。

`is_format_correct === false` 為草稿，其餘為已發布。待審核保留 0 與空結果篩選，不延伸審批流程。搜尋不檢索正文。

「文件標籤管理」只管理既有文件，提供單筆、批次、替換、移除及清除確認，不是正文編輯器。RAG 位於文件清單上方，與原專案 SearchView 的聊天搜尋分開。

上傳、資料夾管理、版本歷史、智慧搜尋、個人空間及系統管理入口會顯示範圍說明。

## 啟動與體驗

可直接開啟 `index.html`；瀏覽器對 file URL 的儲存政策不同，建議透過作品集的靜態 HTTP 服務體驗。訪客只需瀏覽器。

開發者若電腦已有 Node.js，可在此資料夾執行：

```sh
node serve.cjs
```

預覽網址：`http://127.0.0.1:4179/portfolio/demos/knowledge-base/`。此服務僅供本地驗證，部署與訪客都不需要它。可用 `node serve.cjs 4180` 換連接埠。

1. 切換資料夾，搭配關鍵字、狀態、檔案類型；清除篩選後切至第 2、3 頁，試用卡片檢視。
2. 點文件「標籤」或頁首「文件標籤管理」，選擇文件，搜尋標籤並嘗試各種模式。
3. 單筆直接加入；批次保留既有標籤並加入差集；替換以選取集合取代全部。依原介面，已套用標籤不能再次選取，替換模式也相同。需要保留某個既有標籤時，先移除再選取。清空集合請使用「清除全部」及確認視窗。
4. 點「刪除」試用取消與確認，觀察清單、統計和資料夾計數更新。
5. 下載提供隨包附上的真實 PDF、DOCX、Markdown 檔案；每個格式共用一份英文虛構指南，不代表每份文件的完整正文。
6. 輸入「團隊如何整理協作文件？」或「標籤如何管理？」取得固定摘要。等待中不能重複提交。勾選 Source Chunks 查看檔名、Chunk、相似度及內容；再次送出後恢復收合。

## 情境觸發

展開「展示工具」，選擇情境後操作。切換問答情境不會自動送出問題。

| 情境         | 操作與預期                                               |
| ------------ | -------------------------------------------------------- |
| 正常文件     | 文件情境選正常清單                                       |
| 無結果       | 選文件情境「無結果」，或搜尋不存在的標題；清除篩選可恢復 |
| 成功與引用   | 選問答「成功與引用」，輸入任意非空白問題後送出           |
| 無足夠資料   | 選問答「無足夠資料」後送出                               |
| 回答但無引用 | 選問答「回答但無引用」後送出                             |
| 問答錯誤     | 選問答「問答錯誤」後送出，顯示錯誤並可重試               |
| 問答逾時     | 選問答「問答逾時」後送出，約 1.4 秒顯示逾時提示          |
| 刪除失敗     | 選刪除「刪除失敗」，點任一文件刪除並確認；文件及統計不變 |
| 空白送出     | 問題清空或只輸入空白，送出按鈕停用                       |

問答一般延遲約 0.7 秒，逾時採縮短的固定情境，並非等待真實 API 逾時。回答僅依固定規則選擇資料，不理解任意問題；引用使用尚未刪除的前兩份文件，不受文件清單篩選影響。刪除全部文件後問答顯示資料不足。Top K 未提供可見控制。

## 保存與重設

只使用 `portfolio.knowledge-base.v1.state` 一個 localStorage key，保存標籤與刪除結果。重新載入後沿用；篩選、問答、情境和顯示模式不保存。多個同源的展示副本共用此 key。

「展示工具 → 重設展示資料 → 確認」只移除此 key；不使用 `localStorage.clear()`，不動其他資料。無儲存權限時顯示失敗提示，瀏覽和問答仍可使用，標籤及刪除不會假裝儲存成功。損壞的儲存內容會安全回到初始狀態。

## 複製與 GitHub Pages

將整個 `knowledge-base/` 複製到作品集任意子目錄，例如 `projects/knowledge-base/`。所有執行資源均為相對路徑，內頁使用 `#documents`、`#tags`、`#tags/2`，不需要伺服器重寫。確認 Pages 的發布目錄包含此完整資料夾即可，本次沒有提交、推送或部署。

作品集連結範例：

```html
<a href="./projects/knowledge-base/index.html">文件知識庫與 RAG 問答展示</a>
```

iframe 範例（相對作品集頁面）：

```html
<iframe
  src="./projects/knowledge-base/index.html"
  title="文件知識庫與 RAG 問答互動展示"
  width="100%"
  height="1000"
  style="border:0"
  loading="lazy"
>
</iframe>
```

請避免 sandbox 禁止腳本、下載或同源儲存，否則會限制互動。窄螢幕保留可操作導覽及資料夾；列表允許在表格區內水平捲動，亦可切換卡片。

## 驗證與限制

`node verify.cjs` 會執行規則、HTTP 與 jsdom 互動測試。此驗證腳本使用原專案已安裝的 jsdom；不包含於訪客執行流程。獨立複製後若沒有 jsdom，可只執行 `node serve.cjs` 以瀏覽器人工檢查。

詳見 SOURCE-MAP.md 與 VERIFICATION.md。未經原系統登入後瀏覽器比對；真實瀏覽器 UI 驗證被工具中止。DOCX/PDF 完成格式與結構檢查，未完成頁面渲染校對。建議現代 Chrome、Edge、Firefox、Safari；原生 dialog 與 localStorage 需要瀏覽器支援。
